# CompatSync

Generates the `System.Windows.Forms`-namespace builds of Majorsilence.Forms
(`Majorsilence.Forms.WinFormsShims.Compat`, `.Drawing`, `.Avalonia`) by copying the real source into each
project's git-ignored `generated/` folder and rewriting it. Single-file `dotnet` tool, .NET 10 SDK.

```bash
dotnet run tools/CompatSync/CompatSync.cs -- --project all          # or: core | drawing | avalonia
dotnet run tools/CompatSync/CompatSync.cs -- --project core --force --verbose
```

You rarely run it by hand: each Compat project imports [`CompatSync.targets`](CompatSync.targets), which
runs it before compile and skips it when the sources, the rules and the tool are unchanged (a `.stamp` file
in `generated/`). A cross-process lock makes parallel target-framework builds safe. CI needs only the SDK.

## Why not find-and-replace

The first prototype was exactly that, and compiled after four kinds of fix. Each is now rule-driven:

| Hazard | What the tool does |
|---|---|
| **Strings.** `"Majorsilence.Forms.Backends.AvaloniaPlatformBackend, Majorsilence.Forms.Avalonia"` finds the backend by name; `"Majorsilence.Forms.SpellCheck.en_US.words.gz"` is a resource name. | A name in a string is rewritten only if it is `<declared namespace>.<declared type>`; the assembly after the comma is mapped from `projects.*.sourceAssembly`. Resource names and AppContext switches are left alone. Comments change only inside `cref="…"`. |
| **Lost nesting.** `Majorsilence.Forms.Drawing` saw its parent `Majorsilence.Forms` implicitly; `System.Drawing` is not inside `System.Windows.Forms`. | Every simple name is resolved as the original did (nearest enclosing namespace, per namespace block, only against the project and the projects it references) and a `using` is added where the new home is out of scope. |
| **Collisions.** The original's enclosing-namespace lookup beat usings; the new using can be ambiguous. | An alias (which does win) is emitted where two namespaces in scope declare the name, or the name is in `externalNames`. `fileFixups` covers single-file cases. |
| **Types real WinForms puts elsewhere** (`ContentAlignment` is `System.Drawing`). | `relocations` moves the declaration and rewrites qualified references; mixed namespaces in one file are an error. |
| **Types the framework already has** (`System.Drawing.SystemColors`, `ColorTranslator`, …). | Every generated type is checked against the public types of the running framework; a clash fails the run. `relocations[].drop` removes ours so references bind to the framework's. |

Generated files start with `// <auto-generated/>` and `#nullable enable`.

## Adding a backend or project

1. Add it under `projects` in [`compat-rules.json`](compat-rules.json) (`source`, `sourceAssembly`, `assembly`,
   `output`, `references`, `internalsVisibleTo`).
2. Copy `src/Majorsilence.Forms.WinFormsShims.Compat.Avalonia/*.csproj`, set `CompatSyncProject`, and import
   `CompatSync.targets`. Add the project to the solution and to all three `PACKABLE_PROJECTS` lists (see
   CLAUDE.md).
3. Build. Expect to add a `fileFixups` entry or two for a name that clashes with a third-party type.

## When the build fails

- *"already ships in the .NET framework"* — add the type to a `relocations` entry with `"drop": true`.
- *"mixes types that move to …"* — a file declares both a moved and an unmoved type in one namespace.
- *CS0104 ambiguous reference* in `generated/` — add the name to `externalNames`, or a `fileFixups` alias.
- *"names a type no source project declares"* — a rule outlived the type it was for; delete it.
